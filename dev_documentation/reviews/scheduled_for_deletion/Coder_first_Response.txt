## DECISIONS/QUESTIONS FOR W3X

**Q1 — Charter v1.27 contains an internal delivery-rule conflict that should be corrected before a Stage 5C delivery is governed by it.**

**Proposal to change the rule:** reconcile the older delivery clauses with the new v1.27 base-identification rule.

**Rule as it stands:** C-DELIV-01 now expressly says that the exact-starting-commit requirement has been replaced: the base is the prevailing repository state confirmed with W3X; there is no commit-hash or per-file base-hash requirement. C-DELIV-10 also says delivery/proof machinery must not depend for correctness on a particular `HEAD`, index, or staging state. However, C-DELIV-03 still requires every patch to state an “exact starting commit” and requires W3X to verify it; C-DELIV-04 still requires an “exact starting commit” for a replacement file; and C-DELIV-08 still specifies `git rev-parse --short HEAD` and “verify branch and starting commit”.

**Proposed new rule:** retain C-DELIV-01 and C-DELIV-10 as written, and amend C-DELIV-03, C-DELIV-04 and C-DELIV-08 only where necessary to replace their repository starting-commit/HEAD requirements with the v1.27 base-confirmation model. Patch anchor uniqueness, `git apply --check`, whitespace checks, manual application, `git diff --check`, and separately versioned non-repository input identification should remain unchanged.

**Reason:** the present clauses cannot literally all be satisfied simultaneously. The v1.27 header, C-DELIV-01 itself, the Session Bootstrap Header v1.0, and knowledge item K32 all make clear that removal of the commit-hash requirement was intentional, so this appears to be unreconciled old wording rather than a design dispute. I will **not** silently amend or disregard the charter. Until W3X ratifies a correction, the existing charter remains binding; if this remains unresolved when a delivery requiring those clauses is reached, I would treat it as a stop condition rather than choose an interpretation.

**Recommendation:** ratify a currency-only charter v1.28 correction before Stage 5C delivery mechanics are exercised. It need not delay discussion of the forthcoming Stage 5C scope.
