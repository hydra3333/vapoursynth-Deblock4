### 1. File-Scope Conditional Import Declaration

The most direct way to declare a single, file-scope, conditional import that satisfies all your criteria in Zig 0.16.0 is to use a top-level `const` initialized with a comptime `if` expression.

```zig
const build_options = @import("build_options");

const fd = if (build_options.enable_force_down)
    @import("force_down_debug.zig")
else
    struct {};
```

This pattern meets your design requirements:
* **(a) Conventional Location:** It sits at the top of the file alongside normal imports.
* **(b) Visibly Conditional:** It uses the explicit `build_options.enable_force_down` condition.
* **(c) Type Resolution:** It resolves to the imported module namespace when `true`, and to an empty anonymous struct (`struct {}`) when `false`.
* **(d) Unified Namespace:** Multiple gated sites lower in the file can reference `fd` without re-importing.
* **(e) True Omission:** The compiler does not emit code, strings, or symbols from `force_down_debug.zig` when the option is `false`.

---

### 2. Behavior of Conditional Declarations

In Zig 0.16.0, top-level `const` declarations are evaluated lazily at compile time (comptime). 

When `build_options.enable_force_down` is `false`:
1. The compiler evaluates the conditional initializer of `fd`.
2. The `true` branch containing `@import("force_down_debug.zig")` becomes an untaken branch of a comptime-evaluated `if`.
3. Zig's semantic analyzer discards untaken comptime branches. The file `"force_down_debug.zig"` is not analyzed, its AST is not processed for code generation, and no LLVM IR is generated for it.
4. Consequently, **conditional declarations behave identically to conditional statements** regarding binary omission. No symbols, machine code, or strings from the debug module are compiled into the resulting binary.

#### Recommended False-Branch Value
The empty anonymous struct `struct {}` is the recommended false-branch value. 

In Zig, files (modules) are represented as structs under the hood. Using `struct {}` provides an empty namespace that mimics a module with no public declarations. Other alternatives like `void` or `opaque {}` are less idiomatic because they represent types meant for values or pointers, rather than namespaces.

---

### 3. Use-Site Safety and Compilation Boundaries

At the use sites lower in the file, you must wrap references to `fd` in comptime-known checks:

```zig
if (build_options.enable_force_down) {
    eff = fd.applyMaskOnly(actual);
}
```

#### What happens when `enable_force_down` is `false`?
* Because the condition is a comptime-known `false`, the compiler discards the body of the `if` block.
* The reference to `fd.applyMaskOnly` is never semantically analyzed or type-checked.
* The compilation succeeds, and the binary remains clean of any traces of `force_down_debug.zig`.

#### What happens if there is an unguarded reference?
If a developer accidentally references `fd` outside of a gated block:

```zig
// Accidental unguarded reference
eff = fd.applyMaskOnly(actual); 
```

When `enable_force_down` is `false`, `fd` resolves to `struct {}`. The compiler attempts to resolve `applyMaskOnly` on `struct {}` and fails with a compile-time error:

```text
error: no member named 'applyMaskOnly' in 'struct {}'
```

This provides a strict structural boundary, ensuring that invalid or unguarded references are caught at compile time rather than resulting in silent failures or runtime issues.

### 4. Alternative: Build-System Level Conditional Module

An alternative pattern in Zig 0.16.0 is to handle the condition in `build.zig` rather than in the source file. This allows the source file to unconditionally import a module name, while the build graph decides which source file backs that module.

#### Implementation Example

**build.zig**
```zig
const std = @import("std");

pub fn build(b: *std.Build) void {
    const target = b.standardTargetOptions(.{});
    const optimize = b.standardOptimizeOption(.{});

    // 1. Declare the build-time option
    const enable_force_down = b.option(
        bool,
        "enable-force-down",
        "Enable debug force-down seam",
    ) orelse false;

    const lib = b.addSharedLibrary(.{
        .name = "vapoursynth_plugin",
        .root_source_file = b.path("src/root.zig"),
        .target = target,
        .optimize = optimize,
    });

    // 2. Conditionally select the source file backing the "force_down" module
    const fd_source = if (enable_force_down)
        b.path("src/force_down_debug.zig")
    else
        b.path("src/force_down_stub.zig");

    const fd_module = b.createModule(.{
        .root_source_file = fd_source,
    });

    // 3. Expose the module to the root source
    lib.root_module.addImport("force_down", fd_module);

    // Also pass the option for use-site branch gating
    const options = b.addOptions();
    options.addOption(bool, "enable_force_down", enable_force_down);
    lib.root_module.addOptions("build_options", options);

    b.installArtifact(lib);
}
```

**src/force_down_stub.zig** (The stub file required for this approach)
```zig
// This file is empty.
// Any unguarded attempt to use functions from it when disabled will fail to compile.
```

**src/root.zig**
```zig
const build_options = @import("build_options");
// Unconditional import at source level, resolved by build.zig
const fd = @import("force_down"); 

pub fn process(actual: u32) u32 {
    var eff = actual;
    if (build_options.enable_force_down) {
        eff = fd.applyMaskOnly(actual);
    }
    return eff;
}
```

#### Comparison: Source-Level vs. Build-System Level

| Feature | Source-Level `if (...) @import` | Build-System Module Swap |
| :--- | :--- | :--- |
| **Code Location** | Entirely self-contained in `root.zig` | Logic split between `build.zig` and source |
| **Files Required** | Only `force_down_debug.zig` | Requires an extra `force_down_stub.zig` |
| **Unguarded Safety** | Fails to compile (no member in `struct {}`) | Fails to compile (no member in stub module) |
| **Visual Signal** | Explicitly visible at the top of the file | Looks like a standard unconditional import |

The **Source-Level Conditional Import** (Shape 2 / Question 2) is generally preferred when you want to avoid maintaining extra stub files in your repository and keep the build configuration simple.

---

### 5. Verdict and Proof of Omission

Both the source-level conditional declaration (`else struct {}`) and the build-system level module swap achieve **TRUE OMISSION**.

When `enable_force_down` is `false`, the compiler does not generate LLVM IR for the debug code. There are no symbols, no machine instructions, and no static strings associated with `force_down_debug.zig` in the final dynamic library.

#### Verification Protocol

To verify that the code has been omitted from the final shared library (`.so`, `.dll`, or `.dylib` depending on the platform), you can run the following commands:

1. **Verify absence of symbols:**
   Use `nm` (Unix) to check for symbols from the debug module.
   ```bash
   nm -gDC libvapoursynth_plugin.so | grep -i force_down
   ```
   If omission is successful, this command will return no output.

2. **Verify absence of string literals:**
   If your debug module contains unique string literals (e.g., error messages or log formats), search the binary for them using `strings`.
   ```bash
   strings libvapoursynth_plugin.so | grep "unique_debug_string_here"
   ```
   If omission is successful, the string will not be found.

3. **Verify absence of machine code via disassembly:**
   Disassemble the library using `objdump` and search for the debug function names.
   ```bash
   objdump -d libvapoursynth_plugin.so | grep applyMaskOnly
   ```
   No matching disassembly sections should appear.
